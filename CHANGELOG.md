# Changelog

All notable changes to this project are documented in this file. The format
follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the
application uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

The share-code protocol is versioned independently of the application
(envelope `PMM1`, manifest schema 1; see
[`docs/share-code-protocol.md`](docs/share-code-protocol.md)). Entries that
change what codes look like or which codes are accepted say so explicitly.

A version's section becomes its GitHub release notes
([`docs/releasing.md`](docs/releasing.md)), so each paragraph and list item in it
is one line, and its links are full URLs.

## [Unreleased]

### Added

- **Crusader Kings III.** Paradox Mod Manager now finds Crusader Kings III installed through Steam, reads and edits its playsets, and starts the game directly with the chosen mods. Share codes for Crusader Kings III (`"game":"ck3"`) are now accepted; the share-code format is unchanged (envelope `PMM1`, manifest schema 1), and 0.1.2 and earlier still reject such codes as not supported. As in Stellaris, when two mods change the same file, the later mod in the list wins (observed in Crusader Kings III 1.20.1.2). With no game remembered, the application now opens the first installed game in alphabetical order (Crusader Kings III, Europa Universalis IV, Stellaris), or Crusader Kings III when none is installed.
- **Workshop ID lists.** **Export code** now also offers **Copy Workshop ID list**: the enabled Steam Workshop mods of the active playset in load order, as one line of IDs separated by `|` (for example `3818297502|3149445431|3366734814`). Local and disabled mods are left out, and the dialog says how many; the share code still carries them. The import box also accepts such lists and Steam Workshop links, separated by `|`, commas, spaces or line breaks: every mod is enabled, in list order, for the game selected in the window. Text starting with `PMM` is still read as a share code; the share-code format is unchanged (envelope `PMM1`, manifest schema 1), and ID lists are a separate plain format ([section 8](https://github.com/Giorgi-Apriashvili/pdx-mod-manager/blob/main/docs/share-code-protocol.md#8-workshop-id-lists)).
- **Names in the import preview.** For Workshop mods that are not installed, the import preview now shows their Steam Workshop names and marks items that were not found (deleted, private or friends-only), are banned or belong to another game. The names are kept in the imported playset, so the mod list shows them before the downloads finish. Only the item IDs are sent to the Steam Web API, and never in sessions started with `--no-steam` or `--read-only`.
- **Column widths from the keyboard.** The dividers between the columns and the edges of the mod table's columns can now be moved with the keyboard as well as with the mouse. Tab reaches the divider at the edge of the games column and of the actions column, and the table's column edges as one stop right before the mod list (Ctrl+Left and Ctrl+Right move between the edges). Left and Right move the focused divider, Shift takes larger steps, Home and End give the column its narrowest and widest width and Enter its default width. The widths are kept like dragged ones, and screen readers hear each column's width once the column has it. F1 lists the keys.

### Changed

- **The window fits a 1920x1080 screen at 200 % scaling.** The smallest window is now 900x440 pixels at 100 % instead of 980x600, so a maximized window fits a 1920x1080 screen at 200 % or a 1366x768 screen at 150 %. In a narrow window the toolbar above the mod list shows icons only (their names stay in the tool tips and for screen readers), the filter and sort lists drop their "Show:" and "Sort:" labels, and the playset buttons wrap onto two rows; when the window is too short for everything in the right-hand column, that column scrolls, so **Play** and the reasons it is unavailable can always be reached. The counts below the mod list show just their numbers when the words do not fit (their tool tips have the words), so "Showing N of M" stays in view while a search or filter hides mods. Dialogs no longer grow taller than the window; the import preview, the export dialog and long confirmations scroll, a confirmation also with the arrow, Page Up/Down, Home and End keys. The column widths you choose are kept even while a narrow window squeezes the columns, also when you try to widen a squeezed column.
- **Play can be reached with Tab while it is unavailable.** **Play** used to be skipped by Tab while something blocked it, so the reasons next to it could only be read with a screen reader's own navigation. It now keeps the keyboard focus: it still looks unavailable, screen readers hear "unavailable" and the reasons, which are listed right above it, and Enter, Space or a click list them in a notification instead of starting the game. Its tool tip no longer covers them; with more than four, it lists the ones that do not fit. It also keeps the focus while a launch it started runs, and screen readers then hear "starting".
- **Holding Enter on a button no longer repeats it.** Enter now activates a focused button once per press, as Space does; holding it used to repeat the button's action.
- **Workshop mods that ship their own `.mod` file instead of `descriptor.mod`.** A Steam Workshop item whose folder has no `descriptor.mod` but exactly one other `.mod` file is now described by that file, in every game: it shows as ready, a download through the application finishes instead of failing as unusable, and the mod is registered for the game when you press **Play**. Before, it showed as broken unless the Paradox launcher had registered it. With no `.mod` file it stays broken as before; with several it stays broken, and its details now name them.

## [0.1.2] - 2026-11-07

A way out of an interrupted change that cannot be recovered, and fixes for imports and mod list edits. Installed copies update to this version from the update banner or **Settings > Updates**.

### Added

- **Discard an interrupted change that cannot be recovered.** When **Recover** cannot undo an interrupted configuration change because a backup is missing or damaged, the banner next to Play now offers **Discard this record**. After a confirmation that lists the files, the change no longer blocks Play, its files stay as they are, and the next Play writes the game configuration again; until now the game stayed blocked until the change's folder was moved by hand. Recover also no longer needs the backup of a file that is already back to its original contents.

### Fixed

- **Edits of several selected mods are all or nothing.** When an undo or redo that was still being saved took away one of the selected mods, enabling, disabling, moving or removing the selection changed the other mods without saying so; now nothing changes and a warning says so, and you can simply repeat the edit.
- **Importing over a playset keeps its name.** **Replace existing playset** renamed the replaced playset to the name proposed for a new one, such as "SP (2)" for "SP"; it now keeps its name.
- **Imports with Workshop downloads off leave no cancelled downloads.** In a session started with `--no-steam` or `--read-only`, an import queued the missing Workshop mods and cancelled them at once, so for up to 7 days their details said "The download was cancelled" instead of "Not installed". It now queues nothing, the notification says how to get the mods later (and which ones were already queued or failed before), the import button no longer says they will be queued, and the cancelled downloads left by such imports are removed at the next start.
- **Local mods whose file names read the same are no longer hidden.** When several descriptor files in the game's `mod` folder had names that differ only in characters that are not valid Unicode (shown as �), the mod list showed one of their mods and the others disappeared without a word. They now appear as one broken mod that names every file and asks you to rename them, then rescan, and a playset in which it is enabled cannot be played until then.

## [0.1.1] - 2026-11-07

Two changes to **Play**. Installed copies of 0.1.0 can update to this version from the update banner or **Settings > Updates**.

### Changed

- **Play without a playset.** When no playset is selected, **Play** now starts the game without mods instead of staying unavailable, and a note next to it says so. The game's mod list is emptied through the same journaled write as any launch, so your DLC choices are kept and **Restore pre-launch configuration** brings the previous mods back.
- **Play needs Steam for Steam copies.** Until now a Steam copy of the game could be started with Steam closed. **Play** now stays unavailable until the Steam client is running, and the note next to it says "Steam is not running. Start Steam and sign in, then launch …"; once Steam has started, Play becomes available within a few seconds on its own, and it now does the same after the game or the Paradox launcher closes. A copy from another store that you located by hand starts without Steam, as before. Only whether Steam runs is checked, not whether it is signed in.

## [0.1.0] - 2026-11-06

This is the first release of Paradox Mod Manager, a small Windows program that keeps named playsets of mods for Stellaris and Europa Universalis IV, shares them as copyable codes, downloads missing Steam Workshop mods through your own Steam client and starts the game directly with your mods, without the Paradox launcher. It needs no account, collects no telemetry and goes online only for Workshop downloads you ask for and to check for updates. Download the setup, not the ZIP: from this version on, an installed copy updates itself, while the ZIP does not.

### Added

- **Playsets.** Keep as many named playsets per game as you like: create, duplicate, rename and delete them, or start one from the mods the game currently has enabled. Enable and disable mods, add installed ones and reorder them by drag and drop or with Alt+Up/Down. Changes to the mod list are saved at once and can be undone (Ctrl+Z, Ctrl+Y), and deleted playsets, playsets replaced by an import and removed mods can be brought back from **History**. Search, filters and sorting change only the view, never the load order. A mod's details show its version and tags, warn when it was made for another game version, and list declared dependencies that are missing, disabled or placed after it (matched by name; nothing is changed for you).
- **Share codes.** Export a playset as one line of text (`PMM1.…`) to copy or save to a file, and import a code from the clipboard or a file (Ctrl+E, Ctrl+I). A code carries the exact mods, their order and which of them are enabled; it never contains mod files, paths or anything to run. Before anything changes, the import shows a preview of the game and every entry, installed or missing. Import it as a new playset or replace an existing one, and missing Workshop mods are queued for download. The same mods in the same order do not guarantee identical files or multiplayer checksums, because mod versions can differ. Codes use share-code protocol version 1; a code from a newer version of the application is reported as such.
- **Workshop downloads.** **Download missing** fetches the Workshop mods a playset lacks, and imports queue them on their own. The application subscribes and downloads through your own Steam client, using the game's own Steam library, so Steam must be running and signed in to an account that owns the game. Before subscribing, it asks the Steam Web API whether the item exists and belongs to that game, so a share code cannot subscribe you to a deleted or banned item or to one for another game. Downloads show their progress, can be retried or cancelled, and carry on after a restart. When an item cannot be downloaded automatically, its Workshop page can be opened to subscribe by hand.
- **Direct launch and restore.** **Play** writes the playset into the game's mod configuration (`dlc_load.json` and the Workshop descriptors in the game's `mod` folder) and starts the game's own executable, without the Paradox launcher. When Play is unavailable, the reasons are listed next to it, for example missing mods or the game or the Paradox launcher already running. Every write is journaled with backups: if writing fails or the game does not start, the previous configuration is put back; a change interrupted by a crash or power loss is offered for **Recover** at the next start; and **Restore pre-launch configuration** returns the files to how they were before the last launch from the application, for example before you go back to the Paradox launcher. The launcher's own database is never read or changed.
- **EU4 load order note.** Europa Universalis IV does not use the playset order when two mods change the same file: the mod whose name comes first alphabetically wins (observed in the game). EU4 playsets show this as a closable note above the mod list; the order is still saved, shared and written for the game. In Stellaris the later mod in the list wins.
- **Installer.** Download `ParadoxModManager-0.1.0-windows-x86_64-setup.exe`: it installs for your Windows user without administrator rights, to `%LOCALAPPDATA%\Programs\ParadoxModManager`, with one Start menu entry and an optional desktop shortcut, and uninstalls from the Windows list of installed apps. Playsets, settings and backups are stored in `%APPDATA%\ParadoxModManager` and logs in `%LOCALAPPDATA%\ParadoxModManager`, outside the program folder, so upgrades and uninstalling leave them alone. A failed or cancelled upgrade leaves the previous version working, and a setup never replaces a newer version that is already installed. A portable ZIP is also available, but it does not update itself; extract it to a folder whose path is shorter than about 170 characters.
- **Updates.** Once a day, at the first start of the day, the application asks GitHub whether there is a new version. This is on by default; turn it off in Settings > Updates > **Check for updates automatically**, where **Check for updates** asks at any time. A new version shows a banner in the main window; nothing is downloaded or installed until you click **Update and restart** in an installed copy, and **Not now** hides the banner until the next start. **Update and restart** downloads the new installer, checks its SHA-256 against the release's `SHA256SUMS.txt`, runs it and closes, and the installer starts the new version. It does not install while a Workshop download or a game launch is in progress, nor in a session started with `--profile` or `--no-steam`, and it never offers a pre-release or an older version. A ZIP copy does not update itself; it gets a link to the release page instead. Details: [what it contacts and verifies](https://github.com/Giorgi-Apriashvili/pdx-mod-manager/blob/v0.1.0/docs/updates.md).
- **Accessibility.** Everything works from the keyboard: Tab and Shift+Tab through the controls, F6 between the columns, shortcuts (F1 lists them), context menus with Shift+F10 or the Menu key, and Alt+Up/Down to move mods. Focus is always visible, controls have names and descriptions for screen readers, and launch progress and failures are announced; a listening test with NVDA or Narrator has not been done yet. The light and dark themes (or follow Windows) meet WCAG 2.x AA contrast, and the window was checked at 150 % and 200 % display scaling.
- **Privacy.** No account, no server and no telemetry; your playsets stay on your computer. The application goes online only for Workshop downloads you asked for, including unfinished ones it resumes after a restart (the Steam Web API check sends only item ids, without a key, and Steam does the download), and for the update check, once a day and when you press **Check for updates**, which sends nothing about you but the application's version. Direct launches never pass `-enabletelemetry` to the game, even when the game's launcher settings ask for it. Mod names and other text from mods and share codes are shown as plain text, and the window loads nothing from the network, so a crafted code or mod cannot make it fetch anything. **Copy diagnostics** puts a report with user names and personal paths removed on the clipboard; nothing is sent anywhere automatically.

### Known limitations

- **Windows only:** Windows 10 version 1809 or later and Windows 11, 64-bit; tested on Windows 11. Linux, macOS, the Steam Deck and Proton are not supported.
- **Two games:** Stellaris and Europa Universalis IV, tested with their Steam versions. A copy from another store can be located by hand (**Locate installation…**); that is untested and works with local mods only, because Workshop downloads need the game on Steam. Hearts of Iron IV, Crusader Kings III and Victoria 3 are not supported, and their share codes are rejected.
- **Not code signed:** your browser may say the setup is not commonly downloaded (in Edge choose **Keep**, then **Show more** > **Keep anyway**), and Windows SmartScreen may show "Windows protected your PC" when you start it; choose **More info**, then **Run anyway**.
- **Unrecoverable interrupted changes:** if **Recover** cannot undo an interrupted configuration change because its backup is missing or damaged, Play stays blocked for that game. A way to discard such a record from the application is planned for a later version; until then, [troubleshooting](https://github.com/Giorgi-Apriashvili/pdx-mod-manager/blob/v0.1.0/docs/troubleshooting.md#recover-reports-a-missing-or-damaged-backup) has the manual steps.
- **What is verified:** on 2026-10-29 and 2026-10-30, on Windows 11 with Steam, Stellaris 4.5.2 and EU4 1.37.5, with development builds of this version: detection of the games and their mods, playsets, a share-code round trip, a real Workshop download for each game, direct launches with the loaded mods and their order checked in the games' own logs, and failure cases such as a blocked configuration write and a game that does not start. Later changes were tested with automated tests and read-only runs only, and Stellaris 4.5.3 has not been tested. The [support matrix](https://github.com/Giorgi-Apriashvili/pdx-mod-manager/blob/v0.1.0/docs/support-matrix.md) lists every capability with its evidence; what it does not mark as verified, such as other stores or Steam's offline mode, has not been observed with the real game or store.
- **First release:** no update from one published release to the next has happened yet.
