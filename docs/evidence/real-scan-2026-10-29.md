# Evidence: game adapters against the real EU4 and Stellaris installations

**Date:** 2026-10-29, 21:50-22:30 local time (UTC+4)
**Question:** do the EU4 and Stellaris adapters (`src/games`) describe the real installations of
the development machine correctly: discovery, user data, executable, arguments, environment, mod
identities, versions, `supported_version` warnings, the current `dlc_load.json`, and the files a
launch would write?
**Result:** **Yes, read-only, on Windows 11 for both games**, after three fixes found here (EU4
telemetry argument, `userdir.txt`, registered Workshop items without content). Launching and the
in-game load order were not exercised.

Everything below was read, never written: no file under Steam, the game folders or
`Documents/Paradox Interactive` was changed, no game or launcher was started, nothing was sent to
Steam. User paths are redacted to `~`; Steam account ids are omitted.

The hidden test runs `discover`, `scanMods`, `readCurrentConfiguration` and `buildLaunchPlan` for
the configuration the official launcher last wrote. The plan is only computed: for every
`ConfigWrite` it prints the target and whether the bytes would change, and it checks that each
target lies in the user-data folder. It also regenerates each launcher-written `mod/ugc_<id>.mod`
from the Workshop `descriptor.mod` and compares bytes. A replay step copies the registered
`.mod` files and `dlc_load.json` into a temporary folder, with the Steam library replaced by an
empty one, and scans that copy (the state right after a reinstall, see below).

## Findings and conclusions

| Area | Adapter output vs. real files | Action |
| --- | --- | --- |
| Discovery (both) | One Steam installation each; `StateFlags 4` with `BytesToDownload > 0` is complete (the counters describe the last update) | none |
| Version (EU4) | `v1.37.5.0`, label `EU4 v1.37.5.0 Inca (491d)` from `rawVersion` / `version` | none |
| Executable (both) | `./eu4.exe`, `./stellaris.exe` resolved inside the install folder | none |
| Arguments (EU4) | `exeArgs` asked for `-enabletelemetry` | **fixed**: dropped from default arguments and at launch-plan time, for both games (`GameTraits::droppedArguments`); `-gdpr-compliant` kept |
| User data (EU4) | empty `userdir.txt` | **implemented**: an absolute path in `userdir.txt` now relocates the user data (EU4 and Stellaris, see the strings above); empty here, so the default is used |
| Environment (EU4) | `SteamAppId`/`SteamGameId` = 236850 | required, since EU4 has no `steam_appid.txt`; whether a direct start then runs without a relaunch through Steam is unverified |
| Identities (both) | every `ugc_<id>.mod` is Workshop `<id>`; the 9 + 1 local mods with a `remote_file_id` stay local | none |
| `supported_version` (EU4) | warnings only for `1.34.5` and `1.35.*` (made for older versions); `v1.37.*.*`, `v1.37.*`, `v1.37.5.0` match; no wildcard rule | none |
| `supported_version` (Stellaris) | 23 warnings as recorded before | none |
| Current configuration (both) | every `dlc_load.json` entry resolved, order kept | none |
| Minimum writes (both) | the launch plan for the launcher's current selection writes nothing; regenerated descriptors are byte-identical (27/27, 12/12) | none |
| Registered Workshop items without content (EU4 after the reinstall) | the old scan listed them as `Broken` inventory items, so readiness said "broken" and the import plan did not acquire them | **fixed**: left out of the inventory (logged for diagnostics); `dlc_load.json` references keep their Workshop identity, so they read as missing and can be acquired. The replay shows 8 of 9 EU4 entries (and 10 of 17 Stellaris entries) as Workshop items that are not installed |

Self-review fixes made in the same work (fixture-tested, not triggered by this data): a Workshop
launch never overwrites a `mod/ugc_<id>.mod` that belongs to another mod; descriptors must lie
directly in `mod/`; a `dlc_load.json` holding the same JSON in another layout is not rewritten;
`mod/` prefixes in `dlc_load.json` are matched case-insensitively.

## Not verified

- File override precedence between mods (probe procedure in [`../load-order.md`](../load-order.md)).
- How EU4 interprets a relative path in `userdir.txt` (the adapter ignores relative paths), and
  whether a path there must name the user directory itself (assumed) or a parent folder.
- Linux and macOS.
